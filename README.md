# Юридический ИИ-ассистент ПСБ (legal-bot)

RAG-система для поиска положений в нормативных документах с гарантированным отсутствием галлюцинаций. Строгое цитирование, защита от промпт-инъекций, гибридный поиск, детерминированный фильтр по контрагентам.

---

## Архитектура

Единый Docker-контейнер (multi-stage build): фронтенд собирается через Vite и раздаётся FastAPI как статика. Никаких межсервисных зависимостей, CORS, лишних портов.

1. **Гибридный поиск (Retriever)**:
   - **BM25**: Собственная реализация инвертированного индекса для мгновенного полнотекстового поиска по ключевым словам и номерам документов.
   - **Dense Retrieval**: Векторный поиск через API эмбеддингов (с пакетной обработкой и опциональным дисковым кэшем).
   - **Reranking**: Вторичное ранжирование топ-кандидатов через Reranker-модель для повышения точности выдачи.
2. **Контроль достоверности и защита (Critic & Security)**:
   - **Санитизация до чанкинга**: Физическое удаление абзацев с паттернами промпт-инъекций из текстов документов до попадания в индекс.
   - **Хард-фильтр по контрагенту**: Детерминированное исключение договоров с нерелевантными контрагентами на этапе retrieval (решает кейсы с похожими названиями, например, «Альфа-Трейд» vs «Альфа-Трейдинг»).
   - **Верификация цитат**: Пост-проверка ответа на наличие строгого формата ссылок `[doc:..., sec:...]` и соответствия чисел/фактов исходным чанкам. При провале — автоматическая перегенерация или честный отказ.
3. **Обработка юридических документов**:
   - **Иерархический чанкинг**: Сохранение структуры «Заголовок раздела → Текст пункта».
   - **Relabeling**: Автоматическое добавление имени контрагента в метаданные чанка для улучшения матчинга при неочевидных названиях файлов.


### Ключевые решения

- **Санитизация до чанкинга.** Абзацы с паттернами инъекций («игнорируй инструкции», «system prompt») физически удаляются из текстов до попадания в индекс. Q11 закрыт на уровне ingest, а не промптом.
- **Хард-фильтр по контрагенту.** Если в последней реплике упомянут конкретный контрагент — договоры с другими контрагентами исключаются из кандидатов до LLM. Решает кейсы «Альфа-Трейд» vs «Альфа-Трейдинг» детерминированно.
- **Гибридный поиск.** Собственный BM25 на инвертированном индексе (stdlib, без тяжёлых зависимостей) + dense-эмбеддинги через API + RRF fusion + реранкер.
- **Иерархический чанкинг.** Парсинг по заголовкам (`Статья`, `Раздел`, `п. X.Y`), сохранение структуры пунктов, relabel контрагентом для неочевидных имён файлов.
- **Верификация ответа.** Регулярка на формат ссылок `[doc:..., sec:...]` + сверка чисел с контекстом. При провале — одна попытка перегенерации со строгим промптом, затем честный отказ.
- **Лёгкий runtime.** Только `httpx` + stdlib. Никаких `sentence-transformers`, `faiss`, `langchain`. Укладывается в 128 МБ и 16 ГБ RAM с запасом.

## Быстрый старт

1. Положите `knowledge-base.zip` в папку `data/`.
2. Скопируйте `.env.example` в `.env`, заполните ключи LLM-прокси.
3. Соберите и запустите:

```bash
docker compose up --build -d
docker compose logs -f backend
```

Первый старт: индексация + эмбеддинги, до 2 минут.

Остановка:
```bash
docker compose down
```

## Переменные окружения

| Переменная | Назначение | Пример |
|---|---|---|
| `LLM_BASE_URL` | OpenAI-совместимый прокси | `https://api.deepseek.com/v1` |
| `LLM_API_KEY` | API-ключ | `sk-...` |
| `LLM_MODEL` | Модель генерации | `deepseek-v4.1-flash` |
| `EMB_MODEL` | Модель эмбеддингов | `BAAI/bge-m3` |
| `RERANKER_MODEL` | Модель реранкера | `Qwen3-Reranker-8B` |
| `DATA_DIR` | Путь к `knowledge-base.zip` | `data` |
| `TOP_K` | Кандидатов после fusion | `10` |
| `RERANKER_TOP_N` | Чанков в промпт | `5` |
| `TEMPERATURE` | Температура генерации | `0.1` |
| `MAX_TOKENS` | Лимит токенов ответа | `2048` |
| `MAX_WORKERS` | Параллелизм обработки | `4` |

## Ограничения

- **Законы только в действующей редакции.** Если для ответа нужна устаревшая редакция — система явно сообщает об этом и не делает неподтверждённых выводов.
- **Нет встроенного векторного индекса.** Эмбеддинги считаются через API при старте (или on-demand при недоступности). Для офлайн-режима можно добавить папку `index/` с `vectors.bin`.
- **Оффтоп и приветствия** обрабатываются без вызова LLM — экономия времени и токенов.
- **Диалог** обрабатывается в рамках одного запроса: история передаётся в `retrieve` и `generate_answer`, но не сохраняется между вызовами API.
- **Размер базы знаний** ограничен `MAX_EMBED_CHUNKS` (по умолчанию 3000). При превышении dense-поиск переключается в on-demand режим.
